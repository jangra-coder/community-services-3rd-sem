# Deployment guide

EventPass runs as **one process**: Express serves the API and the built React app. You need a host for that process, a PostgreSQL database, and (optionally) an SMTP account for the ticket emails. Everything below uses free tiers.

> **HTTPS matters.** Browsers only allow camera access on `https://` pages, so the scanner's camera mode needs a proper HTTPS URL. All hosts below give you one automatically.

## Option A – Render (recommended, ~5 minutes)

The repository contains a [Render Blueprint](../render.yaml) that creates the web service and a PostgreSQL database.

1. Make sure `render.yaml` is on your default branch (merge the pull request first).
2. Click the button, or in the Render dashboard choose **New → Blueprint** and pick this repository:

   [![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/jangra-coder/community-services-3rd-sem)

3. Render asks for the values marked *sync: false*. You can leave them all blank for a first deployment:
   - `ORGANIZER_SIGNUP_CODE` – set one if only your team should be able to create organizer accounts.
   - `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` – see [Email](#email-smtp) below. Blank = emails are logged, not sent; tickets are still shown on screen.
4. Click **Apply**. The first build takes 3–5 minutes. Your app is at `https://eventpass-xxxx.onrender.com`.
5. Open `/signup`, create your organizer account, create and publish an event, and register from your phone.

`JWT_SECRET` is generated by Render, `DATABASE_URL` is wired to the database, and `CLIENT_URL` is derived from Render's `RENDER_EXTERNAL_URL`, so QR codes link to the right place. Every push to the default branch redeploys automatically.

**Free-tier limits to know about**

- The web service sleeps after 15 minutes without traffic; the first request afterwards takes ~1 minute. Open the site a few minutes before an event starts.
- **Render's free PostgreSQL database is deleted 30 days after creation.** For anything that must survive longer, use a free [Neon](https://neon.tech) database instead:
  1. Create a Neon project and copy its connection string (it ends in `?sslmode=require`).
  2. In Render → your service → **Environment**, set `DATABASE_URL` to that string.
  3. Delete the `databases:` block and the `fromDatabase` lines from `render.yaml` so Render stops managing a database, then redeploy.

## Option B – Railway

1. **New Project → Deploy from GitHub repo** and select this repository. Railway builds the `Dockerfile`.
2. **+ New → Database → PostgreSQL** in the same project.
3. On the web service, add variables:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `JWT_SECRET` = a long random string (`openssl rand -hex 48`)
   - `NODE_ENV` = `production`, `SERVE_CLIENT` = `true`, `TRUST_PROXY` = `1`
   - optional: `ORGANIZER_SIGNUP_CODE`, `SMTP_*`, `MAIL_FROM`
4. **Settings → Networking → Generate Domain.** `CLIENT_URL` is derived from `RAILWAY_PUBLIC_DOMAIN` automatically.

## Option C – your own server with Docker

Any Linux VM (or a college server) with Docker installed:

```bash
git clone https://github.com/jangra-coder/community-services-3rd-sem.git
cd community-services-3rd-sem
JWT_SECRET=$(openssl rand -hex 48) CLIENT_URL=https://events.example.edu docker compose --profile app up -d --build
```

This starts PostgreSQL, Mailpit and the app on port 4000. Put an HTTPS reverse proxy in front (for example [Caddy](https://caddyserver.com/), which issues certificates automatically):

```
events.example.edu {
    reverse_proxy localhost:4000
}
```

## Email (SMTP)

Any SMTP provider works. Two free options:

| Provider | Settings |
| --- | --- |
| [Brevo](https://www.brevo.com/) (300 emails/day) | `SMTP_HOST=smtp-relay.brevo.com`, `SMTP_PORT=587`, `SMTP_USER=<your Brevo login>`, `SMTP_PASS=<SMTP key from Brevo → SMTP & API>` |
| Gmail with an [app password](https://support.google.com/accounts/answer/185833) | `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USER=you@gmail.com`, `SMTP_PASS=<16-character app password>` |

Set `MAIL_FROM` to a sender address the provider allows, e.g. `EventPass <you@gmail.com>`.

## After deploying – checklist

- [ ] Open the site over `https://` on a phone; the scanner's **Start camera** button should ask for camera permission.
- [ ] Register for a test event and confirm the email arrives (or check the service logs if SMTP is not configured).
- [ ] Scan the emailed QR code with the scanner page – it should turn green, and a second scan should say *Already used*.
- [ ] If you set `ORGANIZER_SIGNUP_CODE`, share it only with your team.
- [ ] Before a real event: open the site once a few minutes early (free tiers sleep when idle) and make sure the venue has mobile data or Wi-Fi.

## Updating

Push to the default branch; Render and Railway rebuild automatically. Database migrations run on start-up (`AUTO_MIGRATE=true`).
